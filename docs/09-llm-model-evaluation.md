# ارزیابی مدل‌های زبانی برای استخراج معیار جست‌وجو

## هدف و معیار پذیرش

مدل در ترب مچ قرار نیست دوره‌ها را رتبه‌بندی کند. وظیفهٔ محدود آن، تکمیل ابهام‌های باقی‌مانده از parser قطعی در متن آزاد فارسی است؛ از جمله بودجه، ساعت هفتگی، مهلت، مهارت، نفی و اولویت‌هایی مانند پروژهٔ عملی و Evaluation.

مدل مناسب باید هم‌زمان این شرایط را داشته باشد:

- خروجی JSON معتبر و مطابق schema تولید کند.
- مقدار ذکرنشده را حدس نزند.
- نفی، اعداد محاوره‌ای و بازه‌های فارسی را درست بفهمد.
- اصطلاحات ترکیبی فارسی و انگلیسی مانند RAG، LangChain و Evaluation را حفظ کند.
- برای جست‌وجوی تعاملی، زمان پاسخ قابل‌قبولی داشته باشد.

ارزیابی‌ها در تاریخ `2026-09-24` روی لپ‌تاپی با پردازندهٔ `i7-4700HQ`، رم ۱۶ گیگابایت و کارت گرافیک `GTX 760M` با ۲ گیگابایت VRAM انجام شدند. در نتیجه مدل‌های محلی عمدتاً روی CPU اجرا شدند. این سخت‌افزار علت اصلی کندی است، اما خطاهای معنایی مانند تبدیل «شش ساعت» به ۱۸۰ ساعت یا معکوس‌کردن نفی را توضیح نمی‌دهد؛ چنین خطاهایی به ظرفیت مدل، دادهٔ آموزشی، quantization و پیروی از دستور مربوط‌اند.

## مدل‌های محلی اجراشده

| مدل | ساختار و سرعت مشاهده‌شده | نتیجه و دلیل ردشدن برای مسیر اصلی |
|---|---|---|
| `qwen3:1.7b` | JSON معتبر؛ میانگین حدود ۳۱ ثانیه. با بهبود prompt پاسخ‌ها حدود ۱۵ تا ۳۵ ثانیه بودند. | مقادیر ذکرنشده را حدس زد، تشخیص داخل/خارج دامنه و بازه‌ها را چند بار اشتباه کرد و در مهلت، نفی و اولویت‌ها پایدار نبود. برای تصمیم مستقیم محصول قابل‌اعتماد نبود. |
| Gemma 4 E2B | حدود ۵۱ تا ۷۲ ثانیه | بعضی نفی‌ها را بهتر فهمید، اما در یک نمونه «شش ساعت» را ۱۰۸ ساعت استخراج کرد. دقت عددی برای ورود به رتبه‌بندی کافی نبود. |
| DeepSeek-R1 7B | حدود ۱۵۷ ثانیه | هم بسیار کند بود و هم چند استخراج معنایی اشتباه داشت؛ برای تجربهٔ تعاملی مناسب نبود. |
| `qwen3.5:9b-q4_K_M` | JSON معتبر در ۹ از ۹ سناریو؛ میانگین ۱۴۰٫۲ ثانیه، بازهٔ ۱۳۰٫۸ تا ۱۵۶٫۵ ثانیه | تشخیص دامنه ۶/۹، بودجه ۷/۹، ساعت ۸/۹، مهلت ۵/۹ و نفی ۱/۳ بود. «رایگان» را صفر نکرد، مهلت ۲۰ هفته را ۸ هفته گرفت، نفی پروژه را معکوس کرد، «شیش ساعت» را ۱۸ تا ۲۴ ساعت دانست و چند فیلد ذکرنشده را حدس زد. هیچ سناریویی کاملاً بدون خطا نبود. |
| `ministral-3:3b-instruct-2512-q4_K_M` | در دو اجرای schema کامل، پس از ۱۴۷ و ۸۹ ثانیه وارد تکرار شد و JSON ناقص ساخت. با schema ساده‌تر، ۳/۳ JSON معتبر و میانگین حدود ۵۶ ثانیه داشت. | با وجود تشخیص درست نفی در آزمون نجات، درخواست RAG را گاهی خارج از دامنه دانست، سطح مهارت را حدس زد، «شیش ساعت» را ۱۸۰ ساعت گرفت، «ده تومن» را استخراج نکرد و پروژه/Evaluation را بدون شاهد فعال کرد. |

مدل embedding موجود در LM Studio نیز بررسی شد؛ embedding برای شباهت معنایی و بازیابی مفید است، اما نمی‌تواند جایگزین استخراج ساختاریافتهٔ معیارها شود.

## گزینه‌های بررسی‌شده اما اجرا‌نشده

- Gemma 4 E4B از مدل‌های ناموفق اجراشده سنگین‌تر بود و روی سخت‌افزار آزمایش انتخاب عملی‌ای محسوب نشد.
- `Qwen3.5-4B-fas-16384` برای کاهش اندازهٔ واژگان فارسی بهینه شده است، اما شواهدی برای بهبود استدلال، نفی یا استخراج عددی آن وجود نداشت؛ نسخهٔ آماده و قابل‌اعتماد Q4 نیز در زمان بررسی در دسترس نبود. با توجه به نتیجهٔ مدل 9B، هزینهٔ دانلود، تبدیل و اجرای آن توجیه نشد. بنابراین این مدل در جدول «اجراشده» قرار ندارد.

## ارزیابی مدل ابری منتخب

پس از ناکافی‌بودن کیفیت یا سرعت مدل‌های محلی، همان سناریوها با API و مدل کم‌هزینهٔ `gpt-6-luna` اجرا شدند. دور نخست ۳۲ فیلد از ۳۵ فیلد را درست استخراج کرد. پس از روشن‌ترشدن قواعد بودجهٔ محاوره‌ای، نفی و مقدار تکی در system prompt، دور نهایی به نتایج زیر رسید:

| معیار | نتیجهٔ دور نهایی |
|---|---:|
| سناریو | ۹ |
| فیلد درست | ۳۵ از ۳۵ |
| فیلد اضافه | صفر |
| دقت دقیق | ۱۰۰٪ |
| میانگین زمان پاسخ | ۴٫۰۶ ثانیه |
| توکن ورودی | ۸٬۶۴۳ |
| توکن خروجی | ۱٬۳۹۴ |
| هزینهٔ کل دور | ۰٫۰۰۱۵۶۱۳ دلار |
| میانگین هزینهٔ هر درخواست | ۰٫۰۰۰۱۷۳۵ دلار |

این نتیجه فقط به مجموعهٔ ارزیابی فعلی مربوط است و تضمین عمومی برای همهٔ متن‌های فارسی نیست. به همین دلیل حتی خروجی `gpt-6-luna` نیز مستقیماً وارد رتبه‌بندی نمی‌شود.

## تصمیم معماری

1. parser قطعی، سریع و قابل‌آزمون مسیر اصلی است.
2. `gpt-6-luna` فقط به‌صورت قابلیت اختیاری و خاموش در حالت پیش‌فرض، ابهام‌های اعلام‌شده را تکمیل می‌کند.
3. پاسخ مدل باید با schema و محدوده‌های محصول اعتبارسنجی شود؛ دادهٔ قطعی parser بر پیشنهاد مدل اولویت دارد.
4. timeout، خطای شبکه، پاسخ نامعتبر یا تناقض باعث fallback فوری به parser محلی می‌شود.
5. پروژه بدون API Key، بدون Ollama و بدون مدل محلی کاملاً قابل اجرا است.
6. رابط provider همچنان OpenAI-compatible باقی می‌ماند تا در آینده بتوان مدل محلی یا ابری دیگری را با همان مجموعهٔ ارزیابی سنجید.

بنابراین انتخاب `gpt-6-luna` نتیجهٔ مقایسهٔ عملی کیفیت، سرعت و هزینه است؛ نه وابستگی رتبه‌بندی به یک مدل ابری و نه ادعای ناتوانی همهٔ مدل‌های محلی.
