# ترب مچ (Torob Match)

ترب مچ نمونه‌ی یک محصول جست‌وجو و مقایسه برای دوره‌ها و بوت‌کمپ‌های فارسی حوزه‌های هوش مصنوعی، داده و برنامه‌نویسی است. محصول نیاز کاربر را از زبان طبیعی به معیارهای قابل‌ویرایش تبدیل می‌کند، همه‌ی گزینه‌های معتبر را نگه می‌دارد و نشان می‌دهد هر دوره با شرایط فعلی یا با چه میزان انعطاف در بودجه، زمان و مهارت قابل انتخاب است.

## وضعیت پروژه

مرحله‌ی فعلی: **نمونهٔ تعاملی High-fidelity صفحهٔ خانه و نتایج با React پیاده‌سازی شده است.** جست‌وجوی صفحهٔ خانه کاربر را به تجربهٔ نتایج می‌رساند؛ دادهٔ هشت دوره، رتبه‌بندی توضیح‌پذیر، فیلترهای پویا، مقایسهٔ کنارهمی و حالت روشن/تیره به رابط متصل‌اند. این نسخه هنوز استخراج نیاز کاربر با AI ندارد و فقط مجموعهٔ مستند فعلی را جست‌وجو می‌کند.

سناریوی مرجع، سارا، توسعه‌دهنده‌ی بک‌اندی است که می‌خواهد RAG را به محصول شرکت اضافه کند. مقدار شروع او ۵ میلیون تومان، ۱۲ هفته و ۶ ساعت در هفته است؛ این مقادیر نقطه‌ی شروع‌اند و سقف ثابت محصول نیستند.

## ساختار ریپازیتوری

```text
torob-match/
├── README.md
├── docs/                       # تحقیق، مسئله، مشخصات و تصمیم‌ها
├── data/

│   ├── course.schema.json
│   ├── sample-query.json

│   ├── sample-ranking.json

├── src/                        # رابط React و رتبه‌بندی TypeScript
├── public/brand/               # نشان‌های برداری روشن و تیرهٔ ترب مچ

```

راهبرد کامل آزمون‌های منطق، React، یکپارچگی، انتها‌به‌انتها و دسترس‌پذیری در [راهبرد آزمون فنی](docs/07-testing-strategy.md) ثبت شده است.

قرارداد رنگ، فاصله، تایپوگرافی و دسترس‌پذیری High-fidelity در [Foundations طراحی](docs/08-design-foundations.md) و [`data/design-tokens.json`](data/design-tokens.json) نگهداری می‌شود.

## اصول پروژه

- مسئله‌ی کاربر مقدم بر قابلیت‌های نمایشی است.
- AI نیاز آزاد کاربر را ساختار می‌دهد؛ محاسبه و رتبه‌بندی قابل‌آزمون و قطعی‌اند.
- هیچ دوره‌ی معتبر صرفاً به‌خاطر ناسازگاری با مقدار شروع کاربر پنهان نمی‌شود.
- دلیل امتیاز، کمبود، داده‌ی نامشخص و تغییر لازم برای هر گزینه نمایش‌پذیر است.
- داده‌ی نمونه منشأ، تاریخ مشاهده و سطح اطمینان دارد.

## تصمیم فعلی

بازار انتخاب‌شده، دوره‌ها و بوت‌کمپ‌های فارسی یا فارسی‌دسترس برای رسیدن به یک هدف فنی مشخص است. [تحقیق بازار](docs/01-market-research.md)، [مسئله‌ی کاربر](docs/02-user-problem.md)، [مشخصات محصول](docs/03-product-spec.md)، [داده و رتبه‌بندی](docs/04-data-and-ranking.md) و [تصمیم‌های تجربه‌ی نتایج](docs/05-ux-decisions.md) مسیر تصمیم را ثبت می‌کنند.

وایرفریم Low-fidelity قابل‌ویرایش در Figma نگهداری می‌شود. نسخهٔ High-fidelity تعاملی در کد React همین مخزن است:

- [فریم دسکتاپ ۱۴۴۰ پیکسل](https://www.figma.com/design/LkTufDsSn7vnyzsFHTjnGh?node-id=8-2)
- [فریم موبایل ۳۹۰ پیکسل](https://www.figma.com/design/LkTufDsSn7vnyzsFHTjnGh?node-id=9-2)

کنترل بودجه از صفر تا ۳۰ میلیون تومان است. در سناریوی سارا، ۵ میلیون مقدار مطلوب و ۱۰ میلیون مرز انعطاف اولیه است؛ کاربر می‌تواند هر دو را تغییر دهد. زمان و سطح مهارت نیز به همین شکل پویا هستند.

در رابط، بودجه، ساعت هفتگی و مهلت با سه اسلایدر دو‌دسته‌ای تنظیم می‌شوند. بازه‌ها در خلاصهٔ بالای نتایج دیده می‌شوند؛ تاریخ بررسی دوره‌ها در نمایش به شمسی تبدیل می‌شود، در حالی که دادهٔ خام ISO باقی می‌ماند.

برای دیدن نسخهٔ تعاملی روی رایانهٔ خود:

```powershell
npm install
npm run dev
```

نشانی پیش‌فرض: `http://127.0.0.1:5173/`. برای اجرای آزمون‌های مرورگری، Chrome باید روی دستگاه موجود باشد. بار اول وابستگی‌های Node نصب می‌شوند.

برای اجرای رتبه‌بندی مرجع:

```powershell
python -m app.ranking --courses data/courses.json --query data/sample-query.json
```

برای اجرای همهٔ آزمون‌ها و ساخت نسخهٔ نهایی:

```powershell
npm run test:all
```

این فرمان آزمون‌های Python، واحد/کامپوننت React، ساخت TypeScript/Vite و آزمون‌های مرورگری و دسترس‌پذیری در دسکتاپ و موبایل را اجرا می‌کند. داده‌ها در `2026-09-18` مشاهده شده‌اند؛ قیمت و ظرفیت زنده نیستند.
